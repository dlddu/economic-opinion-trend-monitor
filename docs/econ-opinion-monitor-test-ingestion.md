# 테스트 문서: 뉴스 수집 파이프라인 검증

## 검증 대상 AC
- AC1.1: 정기 수집 스케줄링 (PRD: 뉴스 수집 파이프라인)
- AC1.2: 소스별 조회수 상위 N건 수집 (PRD: 뉴스 수집 파이프라인)
- AC1.3: 3개 축 소스 분류·태깅 (PRD: 뉴스 수집 파이프라인)
- AC1.4: Bronze에 원문 링크 + 원문 전체 저장 (PRD: 뉴스 수집 파이프라인)
- AC1.5: 수집 메타데이터 저장 (PRD: 뉴스 수집 파이프라인)
- AC1.6: 수집 실패·중복·누락 처리 (PRD: 뉴스 수집 파이프라인)

## 테스트 시나리오

### 시나리오 1: 주기적 자동 수집 및 주기 변경
- **사전 조건**: 수집 주기가 매시간으로 설정되어 있고, 수집 가능한 소스가 등록되어 있다.
- **실행 단계**: (1) 2개 주기 이상 작업을 가동한다. (2) 주기를 30분으로 변경한다.
  (3) 한 주기 실행을 강제로 누락시킨다.
- **기대 결과**: 설정 주기마다 수집이 트리거되고, 주기 변경이 다음 실행부터 반영되며,
  누락된 실행이 재시도되거나 다음 주기에 보정된다.
- **검증 AC**: AC1.1

### 시나리오 2: 상위 N건 수집과 API 한계 상황
- **사전 조건**: 소스 A는 N=100 설정, 소스 B는 60건만 제공 가능하다.
- **실행 단계**: 두 소스에서 수집을 실행한다.
- **기대 결과**: 소스 A는 상위 100건, 소스 B는 제공 가능한 60건만 수집되고,
  각 소스의 실제 수집 건수가 메타데이터에 기록된다.
- **검증 AC**: AC1.2

### 시나리오 3: 축 태깅 정확성
- **사전 조건**: 한국·미국·전세계 축에 매핑된 소스가 각각 존재한다.
- **실행 단계**: 전 소스에서 수집을 실행한다.
- **기대 결과**: 수집된 모든 항목에 KR/US/GLOBAL 중 하나의 축 태그가 부여되고,
  매핑 규칙대로 분류된다.
- **검증 AC**: AC1.3

### 시나리오 4: 원문 링크·본문 저장과 본문 미확보 처리
- **사전 조건**: 본문 추출이 가능한 기사와 본문 추출이 불가능한 기사를 함께 준비한다.
- **실행 단계**: 두 유형의 기사를 수집·적재한다.
- **기대 결과**: 본문 확보 기사는 링크와 원문 전체가 저장되고, 본문 미확보 기사는 링크가
  저장되며 본문 미확보 상태가 메타데이터에 표시된다.
- **검증 AC**: AC1.4

### 시나리오 5: 필수 메타데이터 완전성
- **사전 조건**: 정상 수집 가능한 소스가 있다.
- **실행 단계**: 한 주기 수집을 실행하고 적재 레코드를 점검한다.
- **기대 결과**: 모든 레코드에 조회수·수집 시각·소스 식별자·축·순위가 채워지고,
  수집 시각으로 시간대별 묶음을 식별할 수 있다.
- **검증 AC**: AC1.5

### 시나리오 6: 실패·중복·부분 장애 격리
- **사전 조건**: 다수 소스 중 하나가 오류를 반환하도록 구성하고, 동일 링크를 중복 노출하는
  소스를 준비한다.
- **실행 단계**: (1) 오류 소스 포함 수집을 실행한다. (2) 중복 링크가 두 번 등장하게 한다.
  (3) 타임아웃 후 재시도를 유발한다.
- **기대 결과**: 한 소스 실패가 전체 수집을 중단시키지 않고, 중복 링크가 식별·처리되며,
  재시도가 동작하고 실패·중복·누락 사실이 기록된다.
- **검증 AC**: AC1.6
