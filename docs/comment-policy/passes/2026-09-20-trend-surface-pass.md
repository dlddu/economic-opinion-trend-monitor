## 제거 — 복원 경로별 근거

이 창의 제거분은 전부 **복원 경로 ②(저장소 문서)** 이고, 특이한 것은 복원처가 **같은 커밋
안에서 함께 열렸다**는 점이다. #80·#79 는 화면을 세우면서 doc-tracker 2026-09 의 변동 이력에
같은 사실을 산문으로 적었다. 주석이 그 산문을 다시 적은 것이라, 이후 트래커만 고쳐지면 주석이
조용히 거짓이 되는 전형적 자리다.

### ⑴ 여정 단계 귀속 6줄 — `Trend.tsx`

**주석이 자기 복원처를 이름으로 지목한다** — 괄호 안 「mockup index, 「흡수된 화면의 판정 경계」」가

단계가 여러 여정 페이지에 흩어질 수 있다.** `trend`가 그 경우다 — `JRN-daily-scan.html`의
`STP-drill-trend`·`STP-shortlist`와 `JRN-axis-contrast.html`의 `STP-verify-in-trend`, **세 단계가
모두 `trend` 귀속**이고 셋 다 구현 `Trend.tsx` 하나가 받는다」. doc-tracker 2026-09 의 #80 행도

없다」**로 같은 원칙을 적고, 같은 문서의 `sentiment`·`fairness` 도입 lede 행이 「구현은 네 단계를

**경로 ① — 바로 아래 네 줄의 코드.** 주석이 서술하는 규칙 자체가 `entryView` 의 본문이다.

```ts
function entryView(params: URLSearchParams, restored: StoredView | null): Partial<StoredView> {
  const axis = parseAxis(params.get("axis"));
  const subject = params.get("subject") || undefined;
  if (axis !== undefined || subject !== undefined) return { axis, subject };
  return restored ?? {};
}
```

`if (axis !== undefined || subject !== undefined) return { axis, subject }` 한 줄이 「쿼리가 **한
조각이라도** 있으면 진입 조건 **전체**를 쿼리가 정한다」와 「쿼리 > 세션」 **둘 다**이다 — `||` 가
「한 조각이라도」이고, `restored` 를 섞지 않고 통째로 반환하는 것이 「전체를 쿼리가 정한다」이며,
`return restored ?? {}` 가 폴백 순서다. 주석 다섯 줄이 코드 한 줄을 풀어 쓴 자리다.

**경로 ② — 같은 커밋이 쓴 design-tracker.** 「승계 표면 전체」 행이 축자로 적는다:

> `Dashboard.tsx` 의 순위 행이 `/trend?axis=<축>&subject=<대상>` 으로 보내고 `Trend.tsx` 가
> `useSearchParams` 로 그 쿼리를 읽어 **쿼리 > 세션** 으로 진입 조건을 정한다(관측 좌표
> `Trend.tsx` ∋ `entryView` …)

같은 행이 실패 모드까지 적는다 — 「초기값이 `restored?.subject` 가 되면서 dash 에서 X 를 눌러도
세션에 남은 다른 대상 Y 의 상세가 열렸다」. 주석 2~3행이 그 문장의 다른 표현이다.

**경로 ② — 같은 커밋이 쓴 doc-tracker 2026-09.** 두 번째 문단이 통째로 여기 있다:

> 이제 `useSearchParams` 로 읽어 **쿼리 > 세션** 으로 진입 조건을 정하고, 쿼리가 한 조각이라도
> 있으면 진입 조건 전체를 쿼리가 정한다 — 축만 넘어온 진입에 세션의 대상을 섞으면 그 축에
> 없을 수도 있는 대상을 묻게 되기 때문이다.

주석 7~8행과 **어순까지 같다.** 경로 ③(PR #81 본문 표)도 같은 문장을 한 번 더 싣는다.
