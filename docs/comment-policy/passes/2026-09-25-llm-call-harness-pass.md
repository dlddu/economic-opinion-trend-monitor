## 판정 표면을 어떻게 뽑았나 (재현 절차)

원장 「읽는 법」의 계수 규약을 코드로 옮겨 **원장 157행 vs 라이브 159파일**을 대조했다. 원장은
정규식이 아니라 `|` split 으로 파싱한다 — 백틱 정규식은 판정 칸 서술 안의 경로까지 긁어 파일 수를
부풀린다.

    ⑴ 행이 없는 파일의 전량         8파일 114줄
    ⑵ 행이 있으나 자란 파일의 증가분 3파일  58줄
    합계 잔여                              172줄

산술이 화해한다: `43(원장 선언) + 129(#141 유입) = 172`.

그중 **`scripts/check-data-format-change.py` 11줄은 사람 몫이라 뺐다.** `main` ruleset 이
`review/manual-approval` 을 필수 status 로 요구하고 그 status 는 이 스크립트가
`format_changed=false` 일 때만 붙는데, 스크립트의 `SENSITIVE_PATHS`(`:43-49`)에 **스크립트 자신**이
등재돼 있어 주석만 고쳐도 PR 이 사람 리뷰 뒤로 간다(게이트 소스 직접 확인 — #127 이후 5항 유지).
무인 몫 161 과 한 덩어리로 묶으면 가벼운 쪽이 사람 일정에 묶여 영구 이월된다.

## 이 패스가 세운 판정 규칙 — 「서사는 ③ 로 닫고, 편집 지점 가드는 남긴다」

두 저작 PR 본문이 설계 판단을 **절 단위로 길게** 적어 두어 경로 ③ 이 이례적으로 두꺼웠다. 그대로
적용하면 유지가 거의 0 이 되는데, 그러면 「이 값이 무엇과 같아야 하는가」를 말하는 줄까지 사라진다.
그래서 규칙을 먼저 세우고 모든 자리에 일관 적용했다.

> 같은 명제가 저작 PR 본문에 있으면 경로 ③ 으로 닫는다. **다만 그 줄이 미래 편집자에게
> 「이 값이 무엇과 같아야 하는가 / 무엇을 넣지 말라 / 이 순서를 바꾸면 무엇이 조용히 깨지는가」를
> 말하면 남긴다.** PR 본문은 편집 지점에서 읽히지 않으므로 그 경우의 비용은 비대칭이고, 이것이
> README「편집 지점에서만 효과가 있는 가드」 조항이 보호하는 것이다.

규칙의 결과가 값으로 갈렸다 — 유지한 46줄 중 **이 창의 몫 14줄은 전부 가드 형태**이고, 제거한
114줄 중 가드는 **하나도 없다.**

  (`ingest-job-calls2.yaml`) — 제거한 서사의 결론만 남긴 가드. 「그래서」로 시작하던 문장을
  단독으로 서게 고쳤다.

  3줄(`run.sh`) — 이 파일이 그 가드의 주인이다. `reused=1` 이 빠지면 캐시가 주기를 넘지 않은 것이라
  시나리오의 한 갈래가 조용히 사라진다.
- **네 갈래가 하나라도 비면 나머지 단정이 조용히 통과하므로 먼저 끊는다** 2줄(spec).
- **수신 건수 등식이 양방향으로 실제 결함을 잡는다** 3줄(spec) — 적으면 기록이 보내지 않은 호출을
  지어낸 것이고, 많으면 제품이 기록하지 않은 호출을 보낸 것이다.
- **모델 이름으로 거르지 않으면 다른 묶음 호출이 섞여 건수 단정이 무의미해진다** · **순서가 보장되지

- **로그 줄이 canned 조회보다 앞이어야 한다** 2줄(`fixtures/llm/server.py`) — 뒤로 옮기면
  `call_failed` 갈래의 프롬프트가 수신 로그에서 빠지고 위 등식이 조용히 깨진다. 그 인과는 코드
