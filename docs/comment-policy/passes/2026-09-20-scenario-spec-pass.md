## 제거한 것 — 시나리오 재진술 (42줄)

16개 시나리오 spec이 **같은 머리 구조**를 공유한다.

```
// 검증 시나리오: econ-opinion-monitor-test-analysis.md#시나리오 3   ← 기계 판독(유지)
//
// 사전 조건은 "…"이고, 기대 결과는 "…"이다.                        ← 제거 대상
//
// 라벨의 정확도는 이 층이 보지 않는다 — …                           ← 유지(단언 설계)
```

세 번째 문단은 테스트 문서의 `- **사전 조건**:` · `- **실행 단계**:` · `- **기대 결과**:` 항목을
따옴표까지 붙여 옮겨 적은 것이다. **바로 윗줄이 그 문서와 앵커를 기계 판독 형식으로 가리키고 있으므로**
복원 경로 ②(저장소 문서)가 완전히 열려 있고, 주석은 자기 복원처를 스스로 지목하는 셈이다.
같은 유형을 initial-pass가 `ac3-6`·`ac3-7`·`ac3-8`에서 이미 제거했다(각 4줄, 「시나리오→AC 연결 설명」).
이 패스는 그 판정을 나머지 시나리오 spec으로 넓힌 것이다.

되풀이가 **이미 거짓이 된 자리**도 하나 나왔다: `ingestion-2` 의 머리는 사전 조건을 `N=100`·`60건`으로
옮겨 적은 직후 "그래서 여기서는 100도 60도 상수로 쓰지 않고 픽스처에서 유도한다"고 말한다 — 상수를
쓰지 않겠다는 문단이 상수를 적고 있었다.

문단이 뒤 문장과 한 덩어리인 6개 파일(`ingestion-2`~`ingestion-6`, `analysis-4`·`analysis-5`)은 통째로
지우지 않고 **인용만 걷어내고 판단은 남겼다**. 예: `analysis-5` 의 "뒤 절이 집계를 요구하므로 이
시나리오도 집계 묶음에서 닫힌다"는 판단이라 유지하되, 가리키는 대상이 사라지지 않도록 "기대 결과의
뒤 절"로 정정했다.

## 유지한 것

spec 주석의 대부분(318줄)은 **테스트가 왜 그 모양으로 단언하는지**이고, 정책이 명시적으로 유지하는 유형이다.

- **관측 설계** — "Gold 를 Gold 와 비교하면 집계가 자기 자신을 증명하는 꼴"이라 Bronze+Silver 에서
  교차표를 독립적으로 다시 센다(`aggregation-2`). 뷰박스 좌표를 모르고도 성립하도록 "0선 높이 ÷ 점유율이
  모든 점에서 같은 상수인가"로 본다(`aggregation-5`).
- **하네스가 사전 조건을 만드는 방식** — 어느 픽스처·어느 주기·어느 Job 이 그 상황을 세우는지.
  `ingestion-7` 은 머리 문단 전체가 이 대응이라 **전량 유지**했다(재진술처럼 보이지만 문서에 없는
  하네스 사실이다).
- **관측되지 않는 것의 경계** — 오늘 Gold 계약에 저신뢰 축이 없어 "분리"가 미분석에만 성립한다는 사실
  (`analysis-5`·`aggregation-4`), 공유 픽스처가 단일 `time_bucket` 이라 다중 버킷 x축이 이 spec 에서
  관측 불가라는 사실(`aggregation-5`).
- **한 번 깨져 본 자리** — `analysis-5` 의 축 경계를 `CELL_SEP` 으로 끊는 근거. 손으로 구분자를
  조립했다가 `cellKey` 의 구분자와 어긋나 단정이 실제로 깨진 실측이 적혀 있다.
- **런타임 제약** — HTTP 상태 줄이 latin-1 이라 한글 message 를 넣으면 클라이언트가 503 이 아니라 전송
  실패를 본다는 함정, 더블 봉투의 `content` 가 **문자열**이어야 `parse_response` 의 파싱 계약이 e2e 에서
  실행된다는 근거(더블이 dict 를 그대로 실으면 그 층이 영영 검증되지 않는다).

## 판단이 갈려 남긴 것

- **`do_<METHOD>` 디스패치 규약 1줄이 두 더블 양쪽 머리에 있다.** 정책의 제거 유형 「다른 파일 주석의
  재진술」은 "설명의 주인에만 둔다"고 하지만, 두 더블은 대등해서 **주인이 정해지지 않는다**. 양쪽 모두
  유지하고 여기에 적는다. (같은 파일의 latin-1 주석은 `피드 더블과 같은 규약이다`로 출처를 지목하는
  형태라 이미 올바른 꼴이다 — 주인을 정할 수 있으면 이 형태로 가는 것이 맞다.)
- **`ingestion-5` 의 "마지막 요구(…)는 `collection_cycle` 이 …인지로 본다"** — 시나리오 요구를 인용하지만
  그 요구가 **어느 단언으로 번역됐는지**의 대응이라 유지했다. 인용만 걷으면 대응이 성립하지 않는다.
- **`econ_aggregation/cli.py` 3줄** — 첫 문장("세 버킷 단위를 모두 산출한다")은 코드로 복원되지만, 뒤
  절("한 차트를 그리는 소비자는 단위 하나를 먼저 고른다")은 **평평하게 읽는 소비자가 중복 계상하는
  자리**를 짚는 데이터 계약 지식이라 한 덩어리로 유지했다.

## 잔여 계수 규약 — 원장이 세지 못하던 327줄
