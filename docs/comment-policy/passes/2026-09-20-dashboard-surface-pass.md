재현했다).

> **기준 커밋을 옮겼다.** 이 패스는 원래 `473b3cc`(잔여 740 — ⑴ 5파일 108 + ⑵ 16파일 632)에서
> 준비됐으나, 준비와 실행 사이에 자매 PR #82(trend-surface-pass)가 먼저 착지해 같은 요약 행과
> 패스 이력 표를 고쳤다. 그대로 머지하면 두 패스가 같은 문자열 자리에 각자의 절대 숫자를 써
> **충돌 없이 조용히 틀린 값**이 남으므로, `50dbd2d` 로 리베이스하고 지문·잔여·행 수를 전부
> 재측정했다. #82 가 건드린 것은 `Trend.*` 뿐이라 이 패스가 판정하는 10줄 자체는 움직이지 않았다.

이 패스는 그 677 중 **소유자가 없는 10줄만** 집는다. 나머지 667줄은 소유자가 있거나(#78 이 `Trace.*`·
`store_test.go`, #76 이 `Fairness.tsx`·`tokens.css` 를 쥐고 있다) 다음 재감지의 몫이다.

### 판정 표면을 수정 중인 열린 PR — 미루지 않은 근거

머지 직전 열린 PR 여섯(#84 · #78 · #76 · #75 · #73 · #72)의 파일 목록을 다시 조회한 결과,

그 파일을 뺐다(`Fairness.tsx` → #70·#76, `tokens.css` → #76). 여기서 빼지 않은 이유는 둘이다.

   새로 더한다**. 이 패스가 지우는 5줄과는 줄이 겹치지 않는다 — 제거 대상 문장(「축을 추측해야

   (`Dashboard.tsx:112-114` · `Dashboard.test.tsx:78-79`)을 비껴간다. 앞 패스들이 파일을 뺀 이유는
   「판정 근거가 낡은 트리에서 세워지는 것」이었는데, 이 패스의 판정 근거(복원 경로 ③ — #81 본문)는

2. **착지 순서와 무관하게 그 31줄이 묻히지 않는다.** 이 패스 뒤 두 파일 **모두 행을 가지므로**,
   #84 가 뒤에 착지하면 그 증가분은 계수 규약 ⑵(행보다 자란 파일의 증가분)로 다음 패스에 그대로

   trend-surface-pass 가 한 번 거부됐던 자리가 바로 이 조건이 깨지는 경우였다.

10줄은 모두 **한 창**(`#81 (squash)`)이 들였고 두 몫에 나뉘어 있었다 — `Dashboard.test.tsx` 7줄은

## 제거한 것 (5줄)

### ① 승계 계약의 근거 — PR 본문이 축자로 복원한다 (`Dashboard.tsx` 3줄)

```
// 승계 계약의 보내는 쪽 — 상세는 지금 보고 있는 축의 이 대상을 열어야
// 한다. 축을 함께 넘기지 않으면 받는 쪽이 축을 추측해야 하고, 그 추측이
// 틀리면 그 축에 없는 대상을 묻게 된다.
```

이 주석을 들인 **바로 그 PR** 의 본문 표 `web/src/screens/Dashboard.tsx` 행이 같은 말을 한다
(경로 ③ — PR 제목·본문·리뷰):

> 대상과 **함께 축**을 넘긴다(`/trend?axis=<축>&subject=<대상>`). 축을 빼면 받는 쪽이 축을 추측해야 하고,
> 그 추측이 틀리면 그 축에 없는 대상을 묻게 된다.

두 번째 문장은 **거의 축자 재진술**이다. 첫 문장(「상세는 지금 보고 있는 축의 이 대상을 열어야 한다」)은
바로 아래 `onClick` 이 `` navigate(`/trend?axis=${axis}&subject=…`) `` 로 그대로 말하므로 경로 ①(코드
자체)이다. 같은 계약을 `docs/econ-opinion-monitor-design-tracker.md` `:309` 가 한 번 더 적는다(경로 ②):
「`Dashboard.tsx` 의 순위 행이 `/trend?axis=<축>&subject=<대상>` 으로 보내고 `Trend.tsx` 가
`useSearchParams` 로 그 쿼리를 읽어 **쿼리 > 세션** 으로 진입 조건을 정한다」.

⇒ 한 계약의 근거가 **주석 3벌 + PR 본문 + 트래커 행**으로 존재했다. 정책이 드는 실패 모드
(「원본만 고쳐질 때 조용히 거짓이 된다」)가 3중으로 열린 자리다.

### ② 같은 문장의 세 번째 사본 (`Dashboard.test.tsx` 2줄)

```
// 승계 계약의 보내는 쪽. 대상만 넘기면 받는 쪽이 축을 추측해야 하고, 그 추측이 틀리면
// 그 축에 없는 대상을 묻게 된다 — 그래서 축·대상이 **함께** 실려야 한다.
```

①과 **같은 문장**이고, 이 파일에서는 설명의 주인도 아니다(제거 유형 「다른 파일 주석의 재진술 —
설명의 주인에만 둔다」). 무엇을 단언하는지는 테스트 이름
`sends both the axis and the subject when a rank row drills into the trend` 가 말하고(경로 ①),
왜 그래야 하는지는 ①이 인용한 PR 본문과 트래커 `:309` 가 말한다(경로 ③·②). 트래커 `:309` 는 이
테스트 이름을 **검증 좌표로 직접 인용**하고 있어, 주석을 지워도 계약 ↔ 단언의 연결은 문서 쪽에 남는다.

이 제거로 `Dashboard.test.tsx` 의 첫 테스트는 이름과 단언만 남는다 — `Trend.test.tsx` · `Sentiment.test.tsx`
의 전량 유지 주석들이 **단언 설계와 픽스처 사실**만 담고 제품 계약의 변호를 담지 않는 것과 같은 형태가 된다.

## 유지한 것 (5줄)

이 셋은 전부 **「테스트가 왜 그 모양으로 단언하는지」**다 — 정책 「유지 대상 › 복원 불가능한 지식」이
이름으로 드는 유형이고, `Sentiment.test.tsx`(21줄) · `Fairness.test.tsx`(16줄) · `Trend.test.tsx` 의
「전량 유지」 판정이 선례다.

- **자동 cleanup 부재 2줄** (`:9-10`) — 「이 레포는 vitest globals 를 켜지 않아 자동 cleanup 이 없다 —
  지우지 않으면 앞 테스트가 남긴 도착 주소가 다음 테스트의 조회에 함께 잡힌다」. `afterEach` 안의
  `cleanup()` 이 **무엇을** 하는지는 이름이 말하지만 **왜 손으로 불러야 하는지**는 `vitest.config` 에
  `globals: true` 가 **없다는 부재**라 어느 파일도 적극적으로 말하지 않는다. `Sentiment.test.tsx` 가
  같은 사실을 「한 document 를 공유해 행 단위로 스코프하는 이유(자동 cleanup 부재)」로 유지했고,
  먼저 착지한 #82(trend-surface-pass)도 `Trend.test.tsx` 의 같은 유형 2줄(「세션 정리 2 — 자동 cleanup
  부재라는 하네스 사실」)을 유지로 판정했다 — **앞 패스의 유지를 뒤집지 않는다.**
- **축 전환 스텁 설계 2줄** (`:92-93`) — 「축 전환 후에도 같은 응답을 돌려주는 스텁이지만, 승계되는 축은
  화면이 **지금 보고 있는** 축이어야 한다 — 응답 본문의 축을 그대로 쓰면 이 단정이 깨진다」. 이것은
  **픽스처가 왜 축에 무감각하게 만들어졌는지**다. 스텁이 축과 무관하게 같은 body 를 돌려주기 때문에
  두 번째 테스트가 「화면 상태를 읽는 구현」과 「응답 본문을 베끼는 구현」을 가른다 — 단언·픽스처 어느
  쪽을 읽어도 이 판별력은 복원되지 않는다. `Trend.test.tsx` 의 「반전 스케일을 잡는다」 유지와 같은 유형.

## 판단이 갈려 남긴 것

**`Dashboard.test.tsx:53` 의 JSDoc 1줄** — `/** 라우트가 실제로 어디로 갔는지 읽는다 — 링크 문자열이
아니라 도착 주소를 단정한다. */`

제거 쪽 근거: PR #81 본문의 `Dashboard.test.tsx` 행이 「도착 주소를 라우트로 읽어 링크 문자열이 아니라
**실제 네비게이션**을 단정한다」고 거의 같은 말을 한다(경로 ③). ①·②와 같은 성격이다.

유지 쪽 근거: ⑴ 이 줄은 `Landing` 이라는 **local 헬퍼의 doc 주석**이고, 그 이름은 「도착 주소를 읽는
장치」라는 역할까지는 말하지 않는다. ⑵ 담긴 것이 제품 계약의 변호가 아니라 **단언 설계**
(무엇을 단언 대상으로 고를 것인가)라 위 「유지한 것」 둘과 같은 유형이다. ⑶ #81 본문의 해당 문장은
이 헬퍼가 아니라 그 PR 이 파일을 신설했다는 사실 서술의 일부다.

정책의 **「애매하면 남긴다」**(중복 주석의 비용은 작지만 유일한 지식을 지우면 어디에도 남지 않는다)를
적용해 유지한다. 다시 볼 시점: `web/src/` 의 다른 테스트가 같은 「도착 주소를 라우트로 읽는다」 헬퍼를
두 번째로 가질 때 — 그때는 「다른 파일 주석의 재진술」로 설명의 주인을 한 곳에 정해야 한다.
