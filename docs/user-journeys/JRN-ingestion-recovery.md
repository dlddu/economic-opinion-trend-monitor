## 1. 서비스 개요 (참고)

**경제 여론 추세 모니터** — 한국·미국·전세계 3축의 조회수 상위 경제 뉴스를 매시간 수집해, 서술 대상별 관심 추세와 분위기를 시각화한다.

제품 가치 정의는 `docs/econ-opinion-monitor-values.md` 참조.

## 2. 여정 정의

**대상 사용자 (페르소나)**
이도현(가명), 31세, 파이프라인 운영 데이터 엔지니어 (가정). 수집 워크플로(Argo CronWorkflow)와 Bronze 적재를 책임진다. 소비자 화면보다 로그·적재량 지표를 먼저 본다.

> **범위 주의**: 이 제품이 순수 관찰자용 분석 도구라면 P2 여정은 범위 밖일 수 있다. 가치 문서가 V5에 재처리·감사 가능성을 명시하므로 포함했다. 범위 확정 시 조정 가능. (기존 여정 문서의 판단을 승계)

**진입 맥락**
운영 알림 또는 정기 점검으로 진입한다. 소비자 화면에서 "데이터가 이상하다"는 제보를 받고 들어오는 경로도 있다.

**트리거**
시간대별 수집량이 평소 대비 급감·급증했거나, 동일 기사가 중복 적재된 정황이 보인다.

**사용자 목표**
누락·중복 구간을 특정하고 원인을 짚어 보정해, 추세 집계가 잘못된 전제 위에 서지 않게 한다.

**완료 기준**
이상 구간을 시간·소스 단위로 특정하고 재수집 또는 중복 정리를 실행한 뒤, 해당 구간의 수집량이 정상 범위로 복구됨을 확인. 로그로 확인 가능.

## 3. 단계별 상세

### `STP-spot-anomaly` 수집 이상 인지

- **사용자 행동**: 시간대별 수집 건수·실패 건수를 훑어 비정상 구간을 찾는다 (AC1.6)
- **터치포인트**: `reprocess.html` 무결성 패널(`PAT-integrity-panel`) / 운영 대시보드·알림(제품 외부)
- **생각·감정**: "새벽 3시대가 비었는데"
- **페인포인트 / 이탈 위험**: 수집 0건과 "수집 시도 실패"가 같은 모습이면 이상을 놓친다 → 시도·성공·실패·중복을 분리해 표기

### `STP-locate-gap` 누락·중복 구간 특정

- **사용자 행동**: 이상 구간을 시간 단위·소스 단위로 좁힌다 (AC1.5, AC1.6)
- **터치포인트**: `reprocess.html` 무결성 테이블(`CMP-table`)
- **생각·감정**: "전체가 아니라 이 소스 하나였네"
- **페인포인트 / 이탈 위험**: 축·소스별로 쪼개 볼 수 없으면 전 구간 재수집이라는 과잉 대응을 하게 된다 → 축(AC1.3)·소스·시간 3중 필터 제공

### `STP-diagnose-source` 원인 진단

- **사용자 행동**: 스케줄 미실행, 소스 API 오류, 링크 중복(AC1.6)/본문 중복(AC1.7) 중 무엇인지 가른다
- **터치포인트**: `reprocess.html` 상태 배지(`CMP-badge`), 수집 메타데이터(`CMP-kv`) / 워크플로 로그(제품 외부)
- **생각·감정**: "스케줄이 안 돈 건지 소스가 죽은 건지부터 봐야 해"
- **페인포인트 / 이탈 위험**: 실패 사유가 저장되지 않으면 매번 외부 로그를 뒤져야 한다 → 실패 사유를 수집 메타데이터에 남기고 화면에 표시 (AC1.5)

### `STP-backfill` 재수집·중복 정리 실행

- **사용자 행동**: 특정 구간을 재수집하거나 중복 레코드를 정리한다 (AC1.6, AC1.7)
- **터치포인트**: `reprocess.html` 실행 컨트롤
- **생각·감정**: "이번엔 중복 안 쌓이게 해야 하는데"
- **페인포인트 / 이탈 위험**: 재수집이 기존 Bronze를 덮어쓰면 원문 추적성이 깨진다 → content-addressed 저장으로 수정 버전을 보존하고 덮어쓰기 금지 (AC1.7)

### `STP-verify-integrity` 복구 확인

- **사용자 행동**: 보정 후 해당 구간의 수집량·중복률이 정상 범위인지 재확인한다
- **터치포인트**: `reprocess.html` 무결성 패널
- **생각·감정**: "이제 집계 다시 믿어도 되겠다"
- **페인포인트 / 이탈 위험**: 보정 이력이 남지 않으면 나중에 그 구간 수치가 왜 다른지 설명할 수 없다 → 보정 이력을 구간 메타로 기록하고 소비자 화면에도 주석 노출 (백로그 후보)

## 4. 분기·예외 흐름

| 상황 | 처리 | 이어지는 단계 |
|---|---|---|
| 소스 API 자체가 장애 (외부 지연) | 재시도 예약 후 대기, 구간을 "복구 대기"로 표시 | `STP-backfill` (해소 후 재진입) |
| 원본이 이미 내려가 재수집 불가 | 영구 누락으로 확정 표기하고 집계에서 "데이터 없음" 처리 | `STP-verify-integrity` |
| 재수집이 중복을 다시 만듦 | 링크 단위(AC1.6)·본문 단위(AC1.7) 중복 규칙을 재확인 후 정리 | `STP-diagnose-source` |
| 수집은 정상인데 분석 결과가 이상 | 분석 로직 재처리 흐름으로 인계 | `JRN-logic-backfill` · `STP-scope-range` |
| 중도 이탈 (진단만 하고 종료) | 이상 구간을 미해결 상태로 유지해 다음 진입 시 노출 | `STP-locate-gap` |
