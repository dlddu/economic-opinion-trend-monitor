# PRD: 뉴스 수집 파이프라인 (Ingestion / Bronze)

> 대응 요구사항: ①번 — "API 기반으로 매시간 조회수 상위 100개 뉴스 수집"
> 데이터 레이크 계층: **Bronze (원문 보존)**

## 달성 가치
- **V1 (시계열 추세 가시화)** — 정기적·반복적 수집이 추세 데이터의 원천이 된다.
- **V2 (지역 축 간 비교)** — 수집 단계에서 한국·미국·전세계 축으로 소스를 분류·태깅한다.
- **V5 (원문 추적성·재처리)** — Bronze에 원문 링크와 원문 전체를 보존해 역추적·재분석을 보장한다.

## 개요

복수의 뉴스 API에서 조회수 상위 뉴스를 정기적으로 수집해 Bronze 계층에 적재한다.
수집 주기와 건수는 각 API의 제약(rate limit, 제공 가능 개수 등)에 따라 설정으로 조정 가능해야 하며,
기본값은 **매시간 / 소스별 상위 100건**으로 한다. 이 단계는 어떤 가공도 하지 않고 원문을 그대로 보존한다.

### 저장 구조: 관측(news_item)과 본문(news_body)의 분리

매시간 상위 N건을 재수집하는 특성상 같은 기사가 여러 주기에 걸쳐 반복 관측되고, 언론사가 기사를
수정하면 같은 링크의 본문이 주기 사이에 달라질 수 있다. 이를 위해 Bronze는 두 데이터셋으로 나뉜다.

- **`news_item` (관측 레코드)**: 주기마다 1건 — 원문 링크·수집 메타데이터와 함께 본문의
  **콘텐츠 주소(`body_hash` = 본문 원문 바이트의 SHA-256)** 를 참조로 담는다.
- **`news_body` (본문 저장소, content-addressed)**: 본문 원문을 해시를 키로 **버전당 정확히
  한 번** 저장한다. 동일 해시는 다시 저장하지 않고, 수정된 본문은 새 해시의 레코드로 append된다
  (기존 버전 불변 보존). 관측 레코드의 (수집 주기, `body_hash`) 시퀀스가 곧 그 기사의 수정 이력이다.

해시는 본문 원문 바이트 그대로에 대해 계산하며 정규화하지 않는다(정규화는 Silver의 몫 —
Bronze는 관측한 그대로 보존한다).

### 보유 기간 (잠정 결정, 2026-09-24)

Bronze의 두 데이터셋(`news_item`·`news_body`)은 **무기한 보존**한다. 주기가 바뀌어도 이전 주기의
관측 레코드를 삭제하거나 덮어쓰지 않고 누적한다 — 관측 이력(수정 이력·시계열·역추적)은 과거 관측이
남아 있어야 성립하기 때문이다. 보유 상한·아카이빙은 추후 별도로 정리한다.

## Acceptance Criteria

### AC1.1: 정기 수집 스케줄링 (주기 설정 가능)
- **설명**: 수집 작업이 정해진 주기로 자동 실행된다. 기본 주기는 매시간이며, API 제약에 맞춰
  주기를 설정 파일/파라미터로 변경할 수 있다. 실행 누락 시 재시도하거나 다음 주기에 보정한다.
- **달성 가치**: V1
- **검증 방법**: 설정된 주기마다 수집 작업이 트리거되는지, 주기 변경이 즉시 반영되는지 확인한다.

### AC1.2: 소스별 조회수 상위 N건 수집 (건수 설정 가능)
- **설명**: 각 소스에서 조회수 기준 상위 N건(기본 100건)을 수집한다. N은 API가 제공 가능한
  최대치를 초과하지 않도록 소스별로 설정 가능하며, API 제약으로 100건 미만만 제공되는 경우
  제공 가능한 만큼만 수집하고 실제 수집 건수를 메타데이터에 기록한다.
- **달성 가치**: V1
- **검증 방법**: 소스별 N 설정값과 실제 수집 건수, API 한계 상황에서의 동작을 확인한다.

### AC1.3: 3개 축(한국·미국·전세계) 소스 분류 및 태깅
- **설명**: 각 수집 항목에 출처 축(KR / US / GLOBAL)을 태깅한다. 하나의 소스가 단일 축에
  매핑되거나, 소스 내 항목별로 축이 결정될 수 있어야 한다.
- **달성 가치**: V2
- **검증 방법**: 수집된 모든 항목에 축 태그가 부여되는지, 매핑 규칙이 의도대로 적용되는지 확인한다.

### AC1.4: Bronze 레이어에 원문 링크 + 원문 전체 저장 (관측·본문 분리)
- **설명**: 각 뉴스의 **원문 링크(URL)** 는 관측 레코드(`news_item`)에, **원문 전체 텍스트**는
  본문 저장소(`news_body`)에 저장하고, 관측 레코드가 본문 해시(`body_hash`)로 본문을 참조한다.
  모든 관측은 자신이 관측한 시점의 본문 버전 전문으로 정확히 복원 가능해야 한다.
  본문 추출이 불가능하거나 일부만 가능한 경우에도 링크는 반드시 저장하고, 본문 확보 상태를
  메타데이터에 표시하며(`body_available`), 이때 `body_hash`는 빈 값이다.
- **달성 가치**: V5
- **검증 방법**: 저장된 관측 레코드의 링크·해시로 본문 전문이 복원되는지,
  본문 미확보 케이스의 표시(링크 저장 + 빈 해시)를 확인한다.

### AC1.5: 수집 메타데이터 저장
- **설명**: 각 레코드에 조회수, 수집 시각(수집 주기 식별 가능), 소스 식별자, 출처 축,
  순위(상위 N 중 위치)를 함께 저장한다. 이 메타데이터는 시계열 추세와 정규화의 기준이 된다.
- **달성 가치**: V1, V5
- **검증 방법**: 필수 메타데이터 필드가 모두 채워지는지, 수집 시각으로 시간대별 묶음이 식별되는지 확인한다.

### AC1.6: 수집 실패·중복·누락 처리
- **설명**: API 오류·타임아웃 시 재시도하고, 동일 원문 링크의 중복 수집을 식별해 처리하며,
  일부 소스 실패가 전체 수집을 중단시키지 않도록 격리한다. 실패·중복·누락 사실을 기록한다.
  (링크 단위 중복 처리이며, 본문 콘텐츠 단위 중복 제거는 AC1.7이 담당한다.)
- **달성 가치**: V5
- **검증 방법**: 소스 일부 실패, 중복 링크, 재시도 시나리오에서 데이터 무결성이 유지되는지 확인한다.

### AC1.7: 본문 중복 제거·수정 버전 보존 (content-addressed 본문 저장)
- **설명**: 본문은 원문 바이트의 SHA-256 해시를 키로 본문 저장소에 저장한다.
  **수정되지 않은 본문(동일 해시)은 다시 저장하지 않는다** — 주기 반복 관측이든 소스 간
  전재(다른 링크·같은 본문)든 본문 저장소에는 버전당 정확히 1건만 존재한다.
  **수정된 본문(해시 변경)은 새 레코드로 별도 append하고 기존 버전을 삭제·덮어쓰지 않는다.**
  각 관측 레코드는 관측 당시의 본문 해시를 가리키므로, 관측 이력이 곧 기사 수정 이력이 된다.
- **달성 가치**: V5
- **검증 방법**: 동일 본문 반복 수집 시 본문 저장소 건수가 늘지 않는지, 본문 수정 시 새 해시의
  레코드가 추가되고 이전 버전이 보존되는지, 각 관측이 당시 본문 버전으로 복원되는지 확인한다.
