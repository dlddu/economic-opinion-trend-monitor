# 경제 여론 추세 모니터 사용자 여정 문서

> 작업용 제품명: **경제 여론 추세 모니터 (Economic Opinion Trend Monitor)**
> 본 문서는 제품 가치 문서(`econ-opinion-monitor-values.md`)의 가치(V1~V5)를 사용자 흐름으로 옮긴 것이다.
> 각 여정은 하나의 페르소나가 하나의 목표를 달성하기까지의 단계를 정의하며, 달성 가치를 식별자로 참조한다.
> 단계별 시각화(mockup)는 화면 단위 페이지 7개로 정의되어 있으며, 각 단계 표의 `시각화(mockup)` 칸이 그 단계를 담은 페이지를 가리킨다.
> 매핑의 단일 소스는 [`mockups/econ-opinion-monitor-mockup-index.md`](mockups/econ-opinion-monitor-mockup-index.md)이고, 공개 진입점은 문서 허브 [`index.html`](index.html)이다.
> 설계/UX 측 연결 상태는 `econ-opinion-monitor-design-tracker.md`에서 추적한다.

## 페르소나

### P1: 경제 여론 관찰자 (Economic Opinion Observer) — 주 사용자
- **누가**: 시장·정책·산업 동향을 추적하는 분석가·기자·리서처·정보 투자자.
- **상황**: 정기적으로(매일/주간) "지금 경제 여론이 무엇에 쏠려 있고, 어떻게 변하며, 지역별로 어떻게 다르고, 분위기는 어떤가"를 짧은 시간에 파악해야 한다.
- **달성하려는 것**: 서술 대상 기준 추세·비교·분위기를 빠르게 읽고, 신뢰할 수 있는(공정하게 정규화된) 수치인지 확인하며, 이상한 결과는 원문까지 추적해 검증한다.
- **태도**: 데이터의 공정성과 추적성을 중시한다. 정규화 여부와 원문 근거를 따진다.

### P2: 파이프라인 운영자 (Pipeline Operator / Data Engineer) — 보조 사용자
- **누가**: 수집·분석 파이프라인을 운영·유지하는 데이터 엔지니어.
- **상황**: 수집 실패·중복·누락을 점검하고, 분석 로직(서술 대상 추출·분위기 판단 기준)을 개선했을 때 기존 원문을 재처리해 결과를 갱신해야 한다.
- **달성하려는 것**: 원문 추적성을 활용해 데이터 무결성을 유지하고, 로직 변경을 과거 데이터에 안전하게 소급 적용한다.
- **태도**: 무결성·재현성·감사 가능성을 최우선한다.
- **범위 주의**: 이 제품이 순수 관찰자용 분석 도구라면 P2는 범위 밖일 수 있다. 가치 문서가 V5에 "재처리 가능성"을 명시하므로 본 문서에는 포함했다. 범위 확정 시 조정 가능.

## 시각화 현황

- 현재 정의된 mockup: **화면 단위 페이지 7개** (`dash` `trend` `compare` `sentiment` `fairness` `trace` `reprocess` — 각각 CSS·JS를 인라인한 자립형 HTML), 디자인 시스템: **정의됨** (토큰 9 · 컴포넌트 19 · 패턴 9, [`design-system/econ-opinion-monitor-design-system.md`](design-system/econ-opinion-monitor-design-system.md)).
- **시각화 누락 단계(unvisualized step): 없음** — 위 19개 단계 전부가 페이지에 매핑되어 있다(J1 4 · J2 4 · J3 3 · J4 4 · J5 4 = 19/19). 단계별 대응은 각 표의 `시각화(mockup)` 칸과 [`mockups/econ-opinion-monitor-mockup-index.md`](mockups/econ-opinion-monitor-mockup-index.md)의 커버리지 표가 같은 값을 갖는다.
- **공개 진입점**: 문서 허브 [`index.html`](index.html)에서 7개 페이지와 설계 문서로 이동한다. 각 페이지는 빌드·네트워크 없이 `file://`로도 열린다(웹폰트만 CDN).
- 상세 위험 진단과 연결 상태는 `econ-opinion-monitor-design-tracker.md`를 참조한다.

### 알려진 후속 (이 문서 기준의 남은 구조 과제)
현 목업은 **화면 단위**라, "여정 하나를 한 페이지에서 끝까지 걸어본다"는 여정 단위 구조는 아직 아니다. 다음이 후속 과제로 남아 있다.

1. **여정 단위 페이지로의 통합** — J1~J5 각각에 대응하는 페이지 1개(현재는 여정 하나가 여러 화면 파일에 걸쳐 있다).
2. **`data-journey`/`data-step` 속성 규약 도입** — 지금은 문서의 단계 집합과 페이지의 단계 집합을 기계적으로 대조할 수단이 없어, 사람이 표를 읽어야만 확인된다.
3. **단계 식별자의 슬러그 이관** — 현 식별자 `J<n>.<m>`은 표의 행 번호라, 단계를 중간에 추가하면 뒤 번호가 밀리고 인덱스의 참조가 조용히 어긋난다.
4. **J2.4 클릭 어포던스 배선** — `compare`의 대상 행에서 `trend` 상세로 가는 명시적 링크(목적지 화면 자체는 존재).
