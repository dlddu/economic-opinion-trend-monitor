# 테스트 문서: 파이프라인 실행 관측 검증

## 검증 대상 AC
- AC4.1: 배치 실행·단계 기록 (PRD: 파이프라인 실행 관측)
- AC4.2: 기사별 LLM 호출 기록 (PRD: 파이프라인 실행 관측)
- AC4.3: 레코드 ↔ 실행 ↔ 호출 연결 (PRD: 파이프라인 실행 관측)

## 테스트 시나리오

### 시나리오 1: 실행·단계 기록과 건수 정합
- **사전 조건**: 정상 소스와 항상 실패하는 소스가 섞인 수집 구성, 이미 분석된 기사와 새 기사가 섞인
  Bronze, 응답을 제어할 수 있는 모델 더블을 준비한다.
- **실행 단계**: (1) 파이프라인을 1회 실행한다. (2) 모델 호출이 모두 실패하도록 바꿔 한 번 더 실행해
  분석 단계에서 중단시킨다. (3) 스케줄러의 실행 이력을 정리한 뒤 두 실행의 기록을 조회한다.
- **기대 결과**: 두 실행 모두 실행 ID·트리거·시작/종료 시각·최종 상태가 기록된다. 첫 실행은 단계별
  입력 건수가 처리 결과별 건수의 합과 같고, 앞 단계 출력이 다음 단계 입력과 맞물리며, 실패 소스와
  사유가 수집 단계에 기록된다. 두 번째 실행은 분석 단계가 실패로, 중단 시점까지의 건수와 사유가
  기록되고 집계 단계는 실행되지 않았음이 드러난다. 스케줄러 이력 정리 후에도 두 기록이 조회된다.
- **검증 AC**: AC4.1

### 시나리오 2: 기사별 LLM 호출 기록 (정상·파싱 실패·호출 실패·재사용)
- **사전 조건**: 모델 더블이 기사별로 정상 응답, 형식이 깨진 응답, 호출 오류를 돌려주도록 준비하고,
  이전 실행에서 이미 응답을 받은 기사를 하나 포함한다.
- **실행 단계**: (1) 분석을 실행한다. (2) 기사별 호출 기록을 조회하고 전송 프롬프트를 (재구성 방식이면
  재구성해) 모델 더블이 실제로 받은 요청과 비교한다. (3) 로직 버전을 올려 같은 기사를 재처리한 뒤 호출
  기록을 다시 조회한다.
- **기대 결과**: 정상·파싱 실패·호출 실패 기사 모두 호출 기록이 있고, 각각 응답 원문(호출 실패는 오류
  사유)과 파싱 결과 또는 실패 사유, 재시도 횟수, 모델·파라미터, 실행 ID를 가진다. 기록된 프롬프트는
  모델 더블이 받은 요청과 바이트 단위로 같다. 이전 응답을 재사용한 기사는 재사용 사실과 원 호출 기록을
  가리킨다. 재처리 후 새 버전의 호출 기록이 추가되고 이전 버전의 기록은 그대로 남는다.
- **검증 AC**: AC4.2

### 시나리오 3: 레코드·실행·호출 양방향 연결
- **사전 조건**: 분석 완료·저신뢰·미분석(본문 미확보 포함) 레코드가 섞인 Silver와, 범위 지정 재처리로
  두 로직 버전이 병존하는 레코드를 준비한다.
- **실행 단계**: (1) 각 유형의 Silver 레코드에서 호출 기록과 실행 기록으로 이동한다. (2) 실행 기록에서
  그 실행이 만든·갱신한 레코드 목록과 호출 기록 목록으로 이동한다. (3) 병존하는 두 버전 레코드의 연결을
  비교한다.
- **기대 결과**: 모든 레코드가 실행 기록에 도달하고, 모델을 호출한 레코드는 호출 기록(재사용 시 원 호출
  기록)에, 호출하지 않은 레코드는 미호출 사유에 도달한다. 실행 기록에서 출발한 목록이 (1)에서 그 실행을
  가리킨 레코드 집합과 일치한다. 병존하는 두 버전은 서로 다른 실행·호출을 가리키며, 두 버전 모두 AC2.6의
  Bronze 원문으로 역추적된다.
- **검증 AC**: AC4.3
