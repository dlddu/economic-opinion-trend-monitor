# e2e Gold 픽스처

kind e2e가 서빙 경로(픽스처 Gold → Go API → 웹 렌더링) 검증에 쓰는 정적
데이터셋입니다. 배치 파이프라인 없이 결정적으로 검증하기 위해 커밋해 둡니다.

- 레코드는 `contracts/gold/*.avsc` 스키마를 그대로 따릅니다. 스키마를 바꾸면
  이 JSONL과 `tests/e2e/specs/`의 단언(픽스처 subject 문자열 등)을 함께
  갱신하세요. (코드 쪽 계약 드리프트는 `make gen-check`가 방어합니다.)
- subject는 smoke 테스트(`tests/smoke.sh`)의 값과 겹치지 않는 e2e 전용
  문자열(`E2E 검증 서브젝트`)을 사용해 단언 모호성을 없앱니다.
- **세 축(KR·US·GLOBAL)이 모두 `2026-06-23T14` 버킷에 채워져 있습니다.** 3축
  비교(AC3.7)는 "같은 시점에 축을 나란히 둔다"가 검증 대상이라 축 하나라도 비면
  단언이 공허해집니다. 축마다 상위 비율을 일부러 다르게 둬(KR 0.31 · GLOBAL 0.27
  · US 0.20) 축별 스케일과 공통 스케일이 구분되게 했습니다.
- **그 앞의 버킷들이 시계열로 깔려 있습니다**(KR `T11`~`T13`, US·GLOBAL
  `T12`~`T13`). 추세 차트(AC3.5)는 "시간대별 관심도 변화"가 검증 대상이라 한
  버킷만 있으면 그릴 것도 단언할 것도 없습니다. 축마다 버킷 수를 다르게 둬
  (KR 4개 · 나머지 3개) 공통 x축이 축 단위로 계산된다는 것도 관측됩니다.
- **`2026-06-23T14` 행은 고정점입니다.** 과거 버킷은 *덧붙이기만* 하고 최신
  버킷의 값은 한 글자도 바꾸지 않습니다 — 대시보드·비교·정규화 spec 3종이 최신
  버킷을 읽으므로, 이 규칙을 지키는 한 시계열을 늘려도 그 spec들의 기대값은
  움직이지 않습니다. 과거 값은 각 대상의 `spark`(최신 행에 박제된 스파크라인)와
  이어지도록, `delta`는 직전 버킷과의 실제 차이(%p)와 맞도록 골랐습니다.
- 이 픽스처가 시계열을 갖게 되면서, **버킷을 거르지 않는 서빙 경로는 CI에서 바로
  드러납니다** — 최신 버킷만 보아야 할 화면이 묵은 행을 함께 보여주면 대시보드
  spec의 유일성 단언이 깨집니다. 어느 시점을 고르는지에 대한 세부(결측 버킷을
  메우지 않는다, 정렬 순서 등)는 `go/internal/handlers` 단위 테스트가 맡습니다.
